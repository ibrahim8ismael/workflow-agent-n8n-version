# Knowledge Base API

The Knowledge module stores organization-specific business information for agent retrieval. The current implementation accepts Markdown documents only.

All routes are under `/api/v1/knowledge`.

## Supported Operations

| Method | Route | Action |
|--------|-------|--------|
| `POST` | `/knowledge` | Create a Markdown document record |
| `POST` | `/knowledge/ingest` | Create a Markdown document and index its text content |
| `POST` | `/knowledge/upload` | Upload and index a `.md` file |
| `GET` | `/knowledge` | List non-deleted documents |
| `GET` | `/knowledge/:id` | Get one non-deleted document |
| `GET` | `/knowledge/:id/chunks` | Get its active chunks |
| `GET` | `/knowledge/search` | Search active chunks for an organization |
| `PATCH` | `/knowledge/:id` | Edit document metadata or replace Markdown content |
| `DELETE` | `/knowledge/:id` | Soft-delete the document and its chunks |

## Markdown Upload

Upload a real `.md` file as multipart form-data:

```bash
curl -X POST http://localhost:3000/api/v1/knowledge/upload \
  -F "file=@pricing.md" \
  -F "organizationId=org-123" \
  -F "category=pricing" \
  -F "title=Pricing Policy"
```

Rules:

- The multipart field must be named `file`.
- The filename must end in `.md`, case-insensitive.
- The file is decoded as UTF-8 Markdown.
- The maximum content size is 5 MB (`5,242,880` UTF-8 bytes).
- The original filename is stored as `source`.
- If no title is supplied, the filename without `.md` becomes the title.
- The content is split into chunks of up to 1,000 characters with 200 characters of overlap.

## Text Ingestion

Markdown text can also be sent directly as JSON:

```bash
curl -X POST http://localhost:3000/api/v1/knowledge/ingest \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Refund Policy",
    "source": "refund-policy.md",
    "contentType": "markdown",
    "content": "# Refunds\nCustomers may request a refund within 30 days.",
    "organizationId": "org-123",
    "category": "policies"
  }'
```

The same 5 MB UTF-8 byte limit applies to this endpoint.

## Editing a KB

`PATCH` replaces the full Markdown content when `content` is included:

```bash
curl -X PATCH http://localhost:3000/api/v1/knowledge/doc-123 \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Updated Pricing Policy",
    "contentType": "markdown",
    "content": "# Pricing\nPremium costs $25.",
    "category": "pricing"
  }'
```

When content changes, the service updates the document, soft-deletes the old chunks, and creates a fresh chunk set. Metadata-only edits do not reindex chunks. To append information, send the complete new Markdown document with the additional content.

Empty content, non-Markdown content types, and content above 5 MB are rejected.

## Deleting a KB

```bash
curl -X DELETE http://localhost:3000/api/v1/knowledge/doc-123
```

Deletion is soft deletion. The document and all active chunks receive `deletedAt`, and deleted records are excluded from listing, retrieval, and search.

## Retrieval

Search is scoped by `organizationId`:

```bash
curl 'http://localhost:3000/api/v1/knowledge/search?organizationId=org-123&query=refund&limit=10'
```

The runtime uses this service for knowledge retrieval and injects matching chunks into agent context. Current repository search is case-insensitive text containment. The database has a vector column reserved for future semantic embedding search, but embeddings are not generated by the current ingestion pipeline.
