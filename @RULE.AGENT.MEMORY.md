# Woops AI Memory Domain Specification

> Version: 1.0.0
> Status: Draft
> Owner: Woops Architecture Team

---

# 1. Overview

Memory is the long-term information store of an AI Agent.

Its purpose is simple:

> Allow the Agent to remember important information between executions.

Memory is **not** conversation history.

Memory is **not** knowledge.

Memory is **not** a vector database.

Memory is a collection of reusable facts that help the Agent make better decisions.

---

# 2. Philosophy

An AI Employee should behave like a real employee.

A real employee remembers:

- Customer preferences
- Previous conversations
- Important decisions
- Personal information
- Business context

The Agent should do exactly the same.

Memory exists to make the Agent more intelligent over time.

---

# 3. Responsibilities

Memory is responsible for

- Storing important information
- Retrieving relevant information
- Updating information
- Removing outdated information

Memory is NOT responsible for

- Conversation History
- Knowledge Documents
- File Storage
- Embeddings Generation
- AI Reasoning
- Context Building

---

# 4. Design Principles

## Principle 1

Memory stores facts.

Not documents.

---

## Principle 2

Memory is persistent.

It survives between Runs.

---

## Principle 3

Memory belongs to the Agent.

Not the Skill.

Not the Run.

---

## Principle 4

Only meaningful information should be stored.

Never store everything.

---

## Principle 5

Memory should improve future executions.

If information has no future value,

don't store it.

---

# 5. Memory Ownership

Every Memory belongs to

Organization

↓

Agent

↓

User (optional)

↓

Conversation (optional)

Meaning

One Agent cannot access another Agent's Memory unless explicitly allowed.

---

# 6. Memory Types

For MVP we only support three types.

## Conversation Memory

Temporary information related to a conversation.

Examples

- Customer asked about pricing
- Customer uploaded invoice
- Customer requested callback

---

## User Memory

Persistent customer information.

Examples

- Preferred language
- Preferred tone
- Company name
- Job title
- Customer preferences

---

## Agent Memory

Information generated by the Agent.

Examples

- Last summary
- Important decision
- Previous action
- Internal notes

# 9. Memory Operations

The Memory service exposes four operations.

Create Memory

Retrieve Memory

Update Memory

Delete Memory

No other operations are required.

---

# 10. Create Memory

Memory should only be created when information has future value.

Good examples

✓ Customer prefers Arabic

✓ Customer company is Microsoft

✓ Customer works as HR Manager

✓ Customer prefers email communication

Bad examples

✗ Hello

✗ Thank you

✗ How are you

✗ Nice weather today

Never store temporary chat messages.

---

# 11. Retrieve Memory

Before generating a response

the Agent may search Memory.

Flow

Run

↓

Need Memory?

↓

Search

↓

Return Relevant Memories

↓

Inject into Context

↓

Continue

If no Memory exists

continue normally.

---

# 12. Update Memory

When information changes

existing Memory should be updated.

Example

Old

Preferred Language = English

New

Preferred Language = Arabic

Update

Do not create duplicates.

---

# 13. Delete Memory

Delete when

- User requests deletion
- Information becomes invalid
- Organization removes customer
- GDPR / Privacy request

Deletion should be permanent.

---

# 14. Memory Retrieval

Memory retrieval should always be semantic.

Example

User says

"My company is now called Woops AI."

Later

"What company do I work for?"

The Agent should retrieve

Company = Woops AI

without exact keyword matching.

---

# 28. Design Rules

1. Memory stores reusable facts.
2. Memory belongs to the Agent.
3. Memory is persistent.
4. Memory survives between Runs.
5. Memory is not Conversation History.
6. Memory is not Knowledge.
7. Memory should only store valuable information.
8. Skills can read and write Memory.
9. Runs can retrieve and store Memory.
10. Conversation never becomes Memory automatically.
11. Duplicate Memories should be updated instead of recreated.
12. Memory retrieval should be semantic.
13. Every Memory belongs to exactly one Organization.
14. Memory should remain simple during the MVP.
15. Advanced cognitive memory features are intentionally postponed until they solve a real product need.
